Authentication Backend Contract

API requirements for candidate and recruiter registration, login, email verification, forgot password, and reset password.

Frontend ready for API integration

Current frontend status: The auth screens currently use local demo navigation. Registration, login, verification, forgot-password, and reset-password API calls still need to be connected to the backend.
Project: MedHire

Date: September 8, 2026

1. Common API Rules

ItemRequirement
Content typeRequests and responses use application/json.
AuthenticationReturn an access token after successful login. Prefer an HTTP-only secure refresh-token cookie or a secure token strategy.
RolesAllowed values are candidate and recruiter.
PasswordMinimum 8 characters. Recommended: at least one uppercase letter, number, and special character.
Verification codeSix numeric digits. Expire after approximately 10 minutes, allow resend rate limiting, and invalidate after successful use.
Reset tokenSingle-use, short-lived, and invalidated after a successful password reset.
SecurityHash passwords server-side. Never return passwords or expose whether an email exists during forgot-password requests.

2. Candidate Registration

POST/api/auth/register

{
  "role": "candidate",
  "fullName": "Anita Sharma",
  "email": "anita@example.com",
  "phone": "+919876543210",
  "password": "ExamplePassword@123",
  "termsAccepted": true
}

Frontend-only: confirmPassword is checked in the browser and is not sent to the backend. The terms checkbox becomes termsAccepted.

Success: Create the account in an unverified state, send a registration verification code, and return 201 Created.

{
  "message": "Verification code sent",
  "userId": "user_123",
  "email": "anita@example.com",
  "role": "candidate",
  "emailVerified": false
}

3. Recruiter Registration

POST/api/auth/register

{
  "role": "recruiter",
  "fullName": "Rahul Menon",
  "email": "rahul@hospital.com",
  "phone": "+919876543210",
  "designation": "HR Manager",
  "organizationName": "MedCare Hospital",
  "organizationWebsite": "https://hospital.com",
  "city": "Chennai",
  "state": "Tamil Nadu",
  "password": "ExamplePassword@123",
  "termsAccepted": true
}

Frontend-only: confirmPassword is not sent. The UI currently displays the phone country prefix as +91; send the complete E.164 phone number or confirm a separate country-code field with the frontend team.

Success: Create the recruiter account as pending organization verification, send the email verification code, and return 201 Created.

4. Login

POST/api/auth/login

{
  "email": "anita@example.com",
  "password": "ExamplePassword@123",
  "rememberMe": true
}

rememberMe controls token/session duration. It does not need to be stored as a user profile field.

Success: Return 200 OK with session tokens and the authenticated user.

{
  "accessToken": "eyJ...",
  "refreshToken": "refresh-token-value",
  "expiresIn": 3600,
  "user": {
    "id": "user_123",
    "role": "candidate",
    "fullName": "Anita Sharma",
    "email": "anita@example.com",
    "emailVerified": true
  }
}

5. Forgot Password

POST/api/auth/forgot-password

{
  "email": "anita@example.com"
}

Success: Always return a generic response such as 202 Accepted, whether or not the email exists.

{
  "message": "If an account exists, reset instructions have been sent."
}

6. Resend Verification Code

POST/api/auth/resend-code

{
  "email": "anita@example.com",
  "purpose": "registration"
}

For password reset, use "purpose": "password_reset". Rate-limit this endpoint, for example once per 60 seconds per email and IP address.

7. Verify Email or Reset Code

POST/api/auth/verify-code

{
  "email": "anita@example.com",
  "code": "482916",
  "purpose": "registration"
}

For registration, mark the account email as verified and return:

{
  "verified": true,
  "purpose": "registration",
  "user": {
    "id": "user_123",
    "role": "candidate",
    "emailVerified": true
  }
}

For password reset, use "purpose": "password_reset" and return a short-lived reset token:

{
  "verified": true,
  "purpose": "password_reset",
  "resetToken": "reset-token-value"
}

8. Reset Password

POST/api/auth/reset-password

{
  "email": "anita@example.com",
  "resetToken": "reset-token-value",
  "newPassword": "NewExamplePassword@123"
}

Frontend-only: confirmPassword is compared with newPassword in the browser and is not sent.

Success: Invalidate the token, update the password hash, revoke existing sessions if required, and return 200 OK.

{
  "message": "Password reset successfully"
}

9. Error Response Format

{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Please correct the highlighted fields.",
    "fields": {
      "email": "Enter a valid email address."
    }
  }
}
StatusUse
400Invalid request or validation failure.
401Invalid login credentials or invalid reset token.
403Email not verified or recruiter organization not approved.
409Email already registered.
422Business-rule validation failure.
429Too many login, reset, or resend-code attempts.

10. Frontend Integration Checklist

  • Connect candidate and recruiter registration forms to POST /api/auth/register.
  • Connect login and store the returned session securely.
  • Connect forgot-password form to POST /api/auth/forgot-password.
  • Replace the demo verification code 123456 with the backend verification endpoint.
  • Connect resend-code button to POST /api/auth/resend-code.
  • Pass the returned reset token into the reset-password flow.
  • Connect reset-password form to POST /api/auth/reset-password.
  • Display backend validation and authentication errors in the form.
  • Confirm whether the backend uses six-digit OTP verification or emailed reset links.
  • Confirm the final API base URL and authentication token storage policy.
